  O que existe hoje

  ComfyUI-Shared\models só tem modelos de imagem: SDXL (animagine, juggernaut,
  noobai, dreamshaper), FLUX dev (fp8 e GGUF), Qwen-Image-Edit, ControlNet,
  IP-Adapter e LoRAs. A pasta audio_encoders está vazia e não há nenhum modelo
  de voz.

  ComfyUI-Installs (ComfyUI 0.28.2)
  - Os nodes de áudio que vêm no ComfyUI só carregam e salvam áudio, ou geram
    música (ACE-Step, cujo modelo nem está baixado). Nenhum transforma texto em
    voz localmente.
  - Os custom nodes instalados são de imagem, controle e utilidades. Nenhum é de
    áudio.
  - Os únicos nodes de texto para voz são os pagos (ElevenLabs, ByteDance,
    HeyGen), cobrados em créditos do Comfy.org. Usar um deles seria trocar a
    MiniMax por outro serviço pago.
  - O ambiente Python já tem torch 2.10 (CUDA 13.0), torchaudio e transformers
    5.8. A placa é uma RTX 5060 Ti com 16 GB. A base para rodar voz está pronta,
    só falta o modelo.

  Cache do HuggingFace: tem o faster-whisper (large-v3, turbo e medium), que
  transcreve fala em texto, e o HTDemucs, que separa trilhas de áudio. Não
  servem para narrar. O Whisper pode ser útil depois para conferir a pronúncia
  ou alinhar legendas.

  Python direto ou ComfyUI

  Recomendo Python direto:

  1. Encaixa no código atual. A MiniMax é chamada num ponto só (_synthesize em
     video_service.py:111, via MinimaxVoiceClient.synthesize). Um cliente local
     com a mesma assinatura, que recebe texto e devolve bytes, substitui essa
     chamada sem mudar o resto do render.
  2. O ComfyUI só acrescenta etapas. Seria preciso instalar um custom node de
     voz de terceiros, que tende a quebrar quando o ComfyUI atualiza, montar o
     workflow em JSON e ficar consultando a fila. Tudo isso para uma chamada que
     é só texto entrando e áudio saindo.
  3. Evita disputar a placa de vídeo. A spec já aponta esse risco (R4): FLUX,
     LLM e voz na mesma placa. Um modelo leve como o Kokoro roda bem só no
     processador, então a narração nem ocupa a placa.
  4. Funciona no deploy. O sumi-api roda em Docker no servidor de casa (CasaOS),
     que provavelmente não tem placa de vídeo. Um modelo que roda no
     processador pode ir no próprio container, e um que depende do ComfyUI local
     não pode.

  O ComfyUI só valeria a pena se a narração passasse a fazer parte de um
  workflow junto com a animação dos quadros. Isso não é o caso agora.

  O que é

  É um modelo de voz da Resemble AI, ajustado sobre o LTX-2.3 da Lightricks, a
  parte de áudio. O diferencial é a direção de cena escrita no próprio texto,
  que controla emoção, risadas, suspiros, pausas e voz embargada. Exemplo de
  entrada:

  A woman speaks warmly, "Hello!" She sighs deeply. "Hahaha, it's so good to see
  you!"

  Também clona uma voz a partir de 10 segundos ou mais de áudio de referência.
  Para quadrinhos, é exatamente o tipo de expressividade que faria diferença.

  Por que não serve

  Ponto: Idioma
  DramaBox: Só inglês
  Impacto no Sumi: Não atende. Texto em português deve sair com sotaque ou

● Não. O Ollama só gera texto e não suporta nenhum modelo de voz. O pedido para
  ter esse recurso está aberto no GitHub dele desde junho de 2025 e ainda não
  foi implementado.

  - OmniVoice: apesar de ter o Qwen3-0.6B como base, a arquitetura inclui um
    tokenizador de áudio e um processo de geração próprio. O Ollama não sabe
    executar isso, e o modelo não converte para o formato de arquivo que o
    Ollama carrega.
  - Chatterbox, Kokoro e DramaBox: também são modelos de áudio, com a mesma
    limitação.

  Alternativa com o mesmo resultado prático

  Se o que atrai no Ollama é ter um servidor local com o modelo sempre
  carregado, que qualquer app chama por HTTP, dá para montar isso com um serviço
  pequeno em FastAPI:

  tts-server (Python, venv próprio, usando a placa de vídeo)
    POST /synthesize  { text, voice_id }  →  áudio

  - O modelo carrega uma vez na inicialização e fica na memória, como no Ollama.
  - O sumi-api chama esse serviço por HTTP, do mesmo jeito que já chama a
    MiniMax, e continua sem PyTorch no container.
  - Trocar OmniVoice por Chatterbox, ou o contrário, fica restrito a esse
    serviço.

  Existe um projeto pronto nessa linha, o Speaches, que se apresenta como
  "Ollama para voz". Só que ele só roda Kokoro e Piper, e o desenvolvimento está
  parado desde abril de 2026, então não atende.

  O próximo passo continua sendo o teste de audição com OmniVoice, Chatterbox e
  MiniMax. Se aprovar, o modelo vencedor vira esse serviço. Posso começar pelo
